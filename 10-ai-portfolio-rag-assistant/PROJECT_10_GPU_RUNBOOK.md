# Project 10 GPU Upgrade Runbook

This runbook turns the checked-in Vercel-ready starter into the final evaluated Transformer RAG capstone. The offline workflow uses the local NVIDIA GPU; the deployed Vercel app remains a lightweight Next.js application that loads static vectors and calls hosted inference only when configured.

## Final target

The final public version should satisfy all of the following:

- Complete public portfolio corpus: ANN, Simple RNN, LSTM, BiLSTM, CNN, and Transformer.
- Real Transformer embeddings generated by MiniLM or E5-small.
- Small instruction Transformer generation, with a grounded extractive fallback.
- Correct retrieval metrics: Hit Rate@K, Precision@K, Recall@K, MRR, MAP, and nDCG@K.
- Claim-level groundedness, citation precision/completeness, refusal accuracy, and latency percentiles.
- Real JSON/CSV/PNG outputs committed only after the notebook has run successfully.
- Production Vercel latency measured after deployment.

## 1. Use a clean Python environment

For Windows and NVIDIA GPU work, Python 3.11 or 3.12 is recommended for broad ML-package compatibility.

```powershell
cd C:\path\to\transformer-projects\10-ai-portfolio-rag-assistant
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

Install the CUDA-enabled PyTorch command produced by the official PyTorch selector for your Windows, Pip, and supported CUDA configuration. Do this before installing the remaining requirements.

```powershell
# Paste the command produced by https://pytorch.org/get-started/locally/
# Then:
pip install -r requirements-evaluation.txt
python -m ipykernel install --user --name project10-rag --display-name "Project 10 RAG"
```

Verify CUDA:

```powershell
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

Do not proceed with the final GPU evaluation until `torch.cuda.is_available()` prints `True`.

## 3. Open the evaluation notebook

```powershell
jupyter lab notebooks/01-build-and-evaluate-transformer-rag.ipynb
```

Select the **Project 10 RAG** kernel and run the cells from top to bottom.

The notebook performs:

1. GPU diagnostics.
2. Optional GitHub collection.
3. Markdown cleaning and section-aware chunking.
4. Real MiniLM or E5-small document embedding generation on CUDA.
5. Export of Vercel-ready static vectors.
6. Retrieval baseline comparison.
7. Instruction-model answer generation.
8. Claim-level groundedness and citation evaluation.
9. Refusal testing on unsupported questions.
10. Local latency benchmarking.
11. JSON/CSV/PNG artifact generation.
12. Quality-gate checks and automated tests.

## 4. Recommended notebook settings

Start with:

```python
EMBEDDING_PROVIDER = "minilm"
DEVICE = "cuda"
BATCH_SIZE = 64
GENERATOR_MODE = "flan-t5-base"
RUN_GITHUB_COLLECTION = True
INCLUDE_E5 = True
INCLUDE_RERANKER = True
```

For a larger GPU, increase `BATCH_SIZE` to 128 after the first successful run. Reduce it to 32 or 16 if CUDA runs out of memory.

## 5. Equivalent one-command pipeline

After the corpus is collected, the notebook workflow can be repeated from PowerShell:

```powershell
python scripts/run_full_evaluation.py `
  --device cuda `
  --generator flan-t5-base `
  --include-e5 `
  --include-reranker
```

This command intentionally does not collect GitHub files automatically. Corpus collection is a separate safety-controlled step.

## 6. Required quality gates

The notebook reports PASS/FAIL rather than inventing a portfolio rating. Recommended target gates are:

| Gate | Target |
|---|---:|
| Complete category coverage | 6/6 categories |
| Evaluation questions | At least 40 |
| Recall@5 | At least 0.80 |
| nDCG@5 | At least 0.75 |
| Mean groundedness | At least 0.85 |
| Citation precision | At least 0.85 |
| Citation completeness | At least 0.85 |
| Unsupported-question refusal accuracy | At least 0.80 |
| Static data validation | PASS |
| Python and Node tests | PASS |

These are project targets, not guaranteed outcomes. Improve corpus quality, chunking, top-K, embedding model, reranking, or prompt design when a gate fails; do not manually alter result files.

## 8. Validate the Vercel build locally

```powershell
npm install
copy .env.example .env.local
npm run validate:data
npm test
npm run typecheck
npm run build
npm run dev
```

Open `http://localhost:3000`, test source citations, filters, weak-evidence refusal, and `/api/health`.

For real MiniLM query embeddings in local/Vercel runtime, set in `.env.local`:

```text
HF_API_TOKEN=your_server_side_token
HF_EMBEDDING_MODEL=sentence-transformers/all-MiniLM-L6-v2
```

For hosted instruction generation, also set:

```text
USE_HF_GENERATOR=true
HF_GENERATOR_MODEL=your-supported-instruction-model
```

Never use `NEXT_PUBLIC_` for secrets.
