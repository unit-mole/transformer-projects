# DocRank360 Two-Stage Ranking Pipeline Card

This repository documents a portfolio search-ranking pipeline. It does **not**
redistribute or claim ownership of the pretrained model weights.

## Components

| Stage | Python model | Browser model |
|---|---|---|
| Candidate retrieval | `sentence-transformers/all-MiniLM-L6-v2` | `Xenova/all-MiniLM-L6-v2` |
| Candidate reranking | `cross-encoder/ms-marco-MiniLM-L-6-v2` | `Xenova/ms-marco-MiniLM-L-6-v2` |

## Architecture

```text
User query
    ↓
Bi-encoder query embedding
    ↓
Cosine candidate retrieval
    ↓
Top-K documents
    ↓
Cross-encoder query-document scoring
    ↓
Final ranked results
```

## Training status

- New fine-tuning performed by this repository: **No**
- New weight conversion performed by this repository: **No**
- Base models: credited above
- Portfolio contribution: modular retrieval system, evaluation, browser
  deployment, tests, documentation, and responsible-use design

## Dataset

The public demonstration includes:

- 24 synthetic documents;
- 12 synthetic queries;
- 36 graded relevance judgments;
- quality analytics, retrieval, RAG, evaluation, and fictional job-search
  examples.

No confidential company data or personal resumes are included.

## Preprocessing

- HTML entity decoding;
- Unicode NFKC normalization;
- HTML tag removal;
- whitespace normalization;
- missing-value filtering;
- duplicate document removal;
- title and document concatenation;
- relevance validation.

## Evaluation

Required metrics:

- Recall@5 and Recall@10;
- bi-encoder MRR@10;
- reranked MRR@10;
- bi-encoder nDCG@10;
- reranked nDCG@10;
- MRR and nDCG improvement;
- query embedding latency;
- retrieval latency;
- reranking latency;
- total latency.

See `evaluation_results.json`. Values remain `not_run` until generated by the
repository evaluation scripts.

## Deployment

## Intended use

- educational demonstration of two-stage retrieval;
- semantic search over public-safe text;
- portfolio presentation;
- learning retrieval metrics and latency tradeoffs;
- prototyping quality-case or knowledge-base retrieval.

## Not intended use

- consequential employment decisions;
- factual verification;
- confidential or personal data in a public demo;
- production use without security, monitoring, fairness, and domain evaluation.

## Limitations

- the public dataset is small and synthetic;
- browser speed depends on user hardware;
- cross-encoder scores are not probabilities;
- relevant documents can be missed during candidate retrieval;
- reranking can introduce regressions;
- lexical identifiers may require hybrid search.
